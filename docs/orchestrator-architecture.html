Architecture & Implementation Plan

Tầng điều phối nhiều agent trên Wormhole

Thiết kế control plane để phân rã công việc, cấp workspace/Git worktree riêng cho từng agent session, theo dõi tiến độ, kiểm chứng kết quả và hợp nhất thay đổi — không cần agent giao tiếp trực tiếp với nhau.

1. Tóm tắt đề xuất

Đề xuất chính: xây một orchestrator bên ngoài agent.Runtime, dùng pool workspace cố định, mỗi workspace trỏ tới một Git worktree riêng. Orchestrator cấp lease cho task, gọi agent qua fixed MCP endpoint, nhận structured result, tự kiểm chứng bằng Wormhole rồi mới hoàn thành hoặc merge.
Control plane

Orchestrator

Quản lý job, DAG task, scheduler, lease, agent run, artifact, retry, verification và merge.

Execution plane

Wormhole

Cung cấp MCP tools, workspace confinement, Git, process, policy, audit, memory và quality gate.

Reasoning plane

Agent runner

Chạy model/agent cụ thể, nhận task envelope, thao tác trong đúng workspace và trả structured result.

Phạm vi MVP

  • Pool 4 worker workspace và 1 integration workspace.
  • Một Git worktree và branch độc lập cho mỗi workspace.
  • DAG scheduler đơn giản theo priority + dependency.
  • Workspace lease, heartbeat, timeout và quarantine.
  • Kết quả agent bắt buộc có cấu trúc và commit hash khi task có thay đổi code.
  • Verifier độc lập chạy git_status, git_diff, quality_gate, review_diff và tùy chọn security_scan.
  • Merge chỉ thực hiện tại integration workspace.

Không nằm trong MVP

  • Agent-to-agent messaging, mailbox hoặc hội thoại trực tiếp.
  • Provision runtime Wormhole động mà không restart daemon.
  • Cho agent tự quản lý worktree lifecycle hoặc merge vào branch chính.
  • Dùng long-term memory làm task queue hoặc dependency transport.
  • Scheduler tối ưu bằng ML hoặc tự động chia task hoàn toàn không kiểm soát.

2. Nguyên tắc thiết kế

2.1 Không giao tiếp trực tiếp

Agent không gửi message cho nhau. Mọi handoff đi qua orchestrator bằng artifact có version và provenance rõ ràng.

2.2 Một workspace, một active lease

Tại một thời điểm, một workspace chỉ thuộc về một agent run. Unique constraint phải bảo đảm điều này ở tầng database.

2.3 Không tin kết quả agent

Agent result là lời khai. Orchestrator phải xác minh commit, diff, test, lint, build và review bằng execution plane.

2.4 Artifact thay cho conversation

Commit, patch, analysis report, test report, review report và decision record là đơn vị handoff chính thức.

2.5 Workspace pool trước, dynamic runtime sau

Wormhole hiện reconcile daemon khi tập workspace thay đổi. MVP dùng pool cố định để tránh restart ảnh hưởng agent đang chạy.

2.6 Control plane không thao tác repo tùy tiện

Orchestrator chỉ thực hiện lifecycle thao tác đã định nghĩa; mọi coding action vẫn đi qua Wormhole và policy tương ứng.

5. Thành phần chính của orchestrator

01

Job Service

Tạo và quản lý mục tiêu cấp cao, base ref, policy, concurrency limit, deadline và trạng thái tổng.

02

Task Graph

Lưu DAG task, dependency, input artifact, expected output và rule chuyển trạng thái.

03

Scheduler

Chọn task READY, tìm workspace AVAILABLE, áp dụng role/capability và concurrency limit.

04

Workspace Pool Manager

Cấp lease, chuẩn bị branch, reset/clean, kiểm tra health, release hoặc quarantine workspace.

05

Agent Runner Adapter

Chuẩn hóa cách chạy ChatGPT, local CLI agent, API agent hoặc CI worker qua một interface chung.

06

Artifact Store

Lưu commit, patch, report, changed files, decisions, provenance và content hash.

07

Verifier

Độc lập xác minh workspace, commit, diff, tests, build, lint, review và security rules.

08

Merge Manager

Áp artifact vào integration workspace, xử lý conflict, chạy gate tổng và xuất final result.

6.3 Merge flow

  1. Worker task tạo commit artifact trên branch riêng.
  2. Verifier xác nhận commit tồn tại và task output hợp lệ.
  3. Merge Manager acquire lease độc quyền cho integration workspace.
  4. Integration workspace được reset về base integration ref.
  5. Cherry-pick hoặc merge từng commit theo dependency order.
  6. Nếu conflict: tạo conflict artifact và chuyển task sang BLOCKED hoặc tạo resolution task.
  7. Chạy quality gate tổng và review cuối.
  8. Tạo final commit/branch/PR artifact.

7. State machine

7.1 Task state

PENDING→ READY→ ASSIGNED→ RUNNING→ VERIFYING→ COMPLETED
FAILED BLOCKED CANCELLED
TransitionĐiều kiệnSide effects
PENDING → READYTất cả dependency COMPLETED, input artifact tồn tại.Đưa vào scheduler queue.
READY → ASSIGNEDAcquire workspace lease thành công.Tạo agent_run và lease token.
ASSIGNED → RUNNINGRunner start thành công.Ghi started_at, heartbeat deadline.
RUNNING → VERIFYINGRunner trả result đúng lease token và attempt.Đóng tool loop, bắt đầu verifier.
VERIFYING → COMPLETEDVerification pass.Lưu artifacts, release workspace.
VERIFYING → READYLỗi retryable và attempt còn lại.Tăng attempt, cleanup workspace.
* → FAILEDLỗi fatal hoặc hết retry.Lưu failure artifact, release/quarantine.

11. An toàn, identity và cô lập

Workspace isolation

Mỗi agent run thao tác trên Git worktree khác nhau. Không dùng nhiều runtime trỏ cùng working directory.

Lease token

Token sinh ngẫu nhiên, chỉ lưu hash, gắn với task/run/attempt và hết hạn. Result cũ không thể ghi đè run mới.

Runner credential

Mỗi runner chỉ nhận MCP endpoint và credential tối thiểu. Không được truy cập orchestrator database trực tiếp.

Merge privilege

Chỉ Merge Manager hoặc integration runner có quyền thao tác integration workspace và protected branch.

Policy inheritance

Wormhole policy, approval, audit và path confinement vẫn là lớp bảo vệ bắt buộc cho mọi tool call.

Secret handling

Task envelope không chứa secret thô. Secret phải được inject qua runner runtime hoặc environment reference phù hợp.

12. Xử lý lỗi và recovery

Tình huốngPhát hiệnXử lý
Agent treoHeartbeat quá hạn.Đánh dấu run LOST, kiểm tra process/workspace, lưu partial diff, cleanup hoặc quarantine, retry.
Agent trả result muộnLease token/run attempt không còn active.Từ chối result; lưu telemetry nhưng không thay đổi task hiện tại.
Workspace dirty trước taskPrepare check thất bại.Không lease; cleanup; nếu vẫn lỗi thì quarantine.
Wormhole unavailableHealth/MCP call thất bại.Không start run mới; retry với backoff; đánh dấu workspace unavailable.
Verification failTest/lint/build/review không đạt.Tạo verification artifact; retry task hoặc tạo fix task.
Merge conflictCherry-pick/merge exit không thành công.Tạo conflict artifact; BLOCKED hoặc resolution task trong workspace riêng.
Orchestrator restartStartup recovery scan.Load active leases/runs, đối chiếu heartbeat và runner state, tiếp tục hoặc mark LOST.
Database transaction failSQLite error.Không thực hiện external side effect tiếp theo; dùng outbox/event pattern cho thao tác cần retry.

Quy trình lease expiry

  1. Chuyển active run sang LOST_PENDING_INSPECTION.
  2. Không cấp workspace cho run mới ngay lập tức.
  3. Kiểm tra runner process còn sống hay không.
  4. Gọi Wormhole thu git_status, diff và process list.
  5. Lưu partial artifact nếu có giá trị.
  6. Stop process còn sót, cleanup hoặc quarantine.
  7. Chỉ sau đó mới retry task ở workspace khác hoặc cùng workspace đã sạch.

15. Kế hoạch triển khai theo phase

P0

Chốt contract và spike

Mục tiêu: loại bỏ rủi ro kiến trúc trước khi xây scheduler.

  • Chốt task envelope và structured result schema v1.
  • Chốt workspace pool naming, branch convention và lifecycle rule.
  • Spike một agent runner gọi fixed MCP endpoint.
  • Spike verifier đọc status/diff và chạy quality gate.
  • Chốt SQLite schema và state transitions.

Deliverable: ADR, JSON schemas, runnable spike, test plan.

P1

Orchestrator core và persistent state

  • Tạo command/package orchestrator riêng.
  • SQLite migrations, repositories và transaction helpers.
  • Job/task/dependency/artifact CRUD.
  • State transition validation và event log.
  • Startup recovery skeleton.

Exit criteria: tạo job DAG, restart process không mất state, reject transition sai.

P2

Workspace pool và lease

  • Provision sẵn 4 worker worktree + 1 integration worktree.
  • Đăng ký named workspace và health discovery.
  • Acquire/release lease transactionally.
  • Prepare/reset/clean workspace.
  • Heartbeat, expiry và quarantine.

Exit criteria: không thể double-lease; dirty workspace bị chặn; recovery xử lý lease hết hạn.

P3

Agent runner và scheduler

  • AgentRunner interface.
  • Local runner adapter đầu tiên.
  • FIFO/priority scheduler với dependency và concurrency limit.
  • Run heartbeat, cancel, timeout và structured result validation.
  • Artifact ingestion.

Exit criteria: chạy song song N task độc lập, dependency task chỉ chạy đúng thứ tự.

P4

Verifier và retry policy

  • Wormhole MCP client cho verifier.
  • Git/commit/diff verification.
  • Quality gate, review và security policy.
  • Retry classification: retryable/fatal/blocked.
  • Partial artifact khi run thất bại.

Exit criteria: agent khai sai commit/test bị phát hiện; retry không nhận result cũ.

P5

Integration và merge manager

16. Acceptance criteria MVP

  • Có thể tạo một job gồm ít nhất 5 task và dependency DAG.
  • Hai task độc lập chạy đồng thời trên hai workspace khác nhau.
  • Không có trường hợp hai run active cùng lease một workspace.
  • Agent không cần biết hoặc gọi trực tiếp agent khác.
  • Artifact từ task trước được đưa vào task sau qua orchestrator.
  • Agent result sai commit hash bị verifier từ chối.
  • Test failure làm task không thể COMPLETED.
  • Agent mất heartbeat được mark LOST và workspace được inspection trước khi reuse.
  • Result cũ sau retry không thể cập nhật trạng thái task mới.
  • Merge chỉ diễn ra tại integration workspace.
  • Orchestrator restart có thể khôi phục job/task/lease state.
  • Mọi transition quan trọng có event/audit với job_id, task_id, run_id và workspace_id.
