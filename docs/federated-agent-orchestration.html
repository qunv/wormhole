Architecture proposal · 2026-08-01

Điều phối coding agent phân tán giữa nhiều người, nhiều máy và nhiều repository

Mỗi nhân sự sở hữu coding agent và local repository riêng. Agent đăng ký vào một logical workspace trung tâm, nhận task qua resident runner, làm việc bằng Wormhole tại máy cục bộ, rồi publish commit và artifact để kích hoạt công việc phụ thuộc ở cùng repo hoặc repo khác.

1. Tóm tắt giải pháp

Đề xuất: xây dựng một Central Orchestrator quản lý logical workspace, agent registration, workspace dependency, task DAG, artifact và trạng thái run. Trên mỗi máy nhân sự chạy một Agent Runner kết nối outbound tới orchestrator và sử dụng Wormhole để thao tác local repository.

Logical Workspace

Đại diện cho một repository hoặc project logic, không phải một thư mục local duy nhất.

Workspace Registration

Liên kết agent, máy và local clone với logical workspace tương ứng.

Artifact Handoff

Output đã xác minh được chuyển sang task phụ thuộc dưới dạng immutable artifact.

Resident Runner

Kênh đánh thức agent qua WebSocket hoặc long-poll; MCP không đảm nhiệm wake-up.

2. Bài toán cần giải quyết

Trong cùng repository

Nhiều nhân sự có local clone riêng của cùng repository. Khi một task hoàn tất, task phụ thuộc có thể được giao cho agent khác mà không chia sẻ working directory.

Giữa nhiều repository

Backend, Frontend, Mobile hoặc shared library nằm ở các repo khác nhau nhưng có dependency nghiệp vụ và contract cần được truyền giao tự động.

3. Nguyên tắc thiết kế

1. Local-first

Mỗi nhân sự giữ local clone và credential của mình; orchestrator không cần mount trực tiếp repo cá nhân.

2. Outbound connection

Runner chủ động kết nối ra ngoài, giảm yêu cầu mở inbound port vào máy developer.

3. Artifact-driven

Task sau được kích hoạt bởi output versioned đã verified, không phải bởi message mơ hồ hoặc local path.

4. Immutable identity

Mọi run, attempt, commit và artifact có ID/hash bất biến để chống stale result.

5. Independent verification

Không tin tuyệt đối vào lời khai của agent; kiểm tra Git state, test và artifact thực tế.

6. Pluggable agent

Codex, Claude hoặc agent khác được bao quanh bởi adapter chung thay vì nhúng logic vendor vào scheduler.

7. Explicit dependency

Workspace link mô tả quan hệ dài hạn; task dependency mô tả thứ tự công việc cụ thể.

8. Least privilege

Mỗi runner chỉ nhận task của registration hợp lệ và chỉ dùng tool được policy cho phép.

9. Recoverable state

Orchestrator restart phải khôi phục task, run, lease và artifact từ persistent store.

Trách nhiệm theo lớp

Orchestrator

Quyết định task nào READY, chọn registration, cấp lease, lưu state, publish artifact, resolve dependency và audit.

Agent Runner

Duy trì kết nối, nhận assignment, gọi agent adapter, gửi heartbeat, upload result và xử lý cancellation.

Wormhole

Cung cấp execution plane local: file, Git, command, test, policy, audit và context cho agent đang chạy.

Orchestrator không nên trực tiếp thao tác thư mục local của Blob hoặc Alice. Cross-machine handoff phải đi qua Git remote hoặc artifact store.

7.2 Backend → Frontend cross-repo flow

  1. Job được tạo với task Backend và Frontend; Frontend phụ thuộc artifact contract từ Backend.
  2. Scheduler chọn Blob registration có workspace Backend, capability phù hợp và còn capacity.
  3. Blob Runner nhận assignment, launch coding agent và trỏ MCP tới Wormhole local.
  4. Agent sửa code, chạy test, commit và push branch hoặc upload patch/bundle.
  5. Runner trả structured result kèm commit, artifact manifest và check result.
  6. Verifier độc lập xác nhận commit truy cập được, tests pass và contract hợp lệ.
  7. Artifact Service publish OpenAPI, API diff, integration notes và test report.
  8. Dependency Resolver nhận artifact.published, kiểm tra consumer và trigger policy.
  9. Frontend task chuyển từ PENDING sang READY.
  10. Scheduler chọn Alice registration cho workspace Frontend.
  11. Alice Runner nhận task envelope chứa toàn bộ artifact reference và acceptance criteria.
  12. Alice Agent tích hợp client/UI/tests trong repo B, commit và publish result.
  13. Integration Runner chạy contract/E2E validation giữa hai output.

9.1 Thành phần resident trên máy nhân sự

Duy trì WebSocket/long-poll, reconnect, auth refresh và receive assignment.

Workspace Adapter

Kiểm tra local clone, branch policy, base commit, cleanup và Wormhole endpoint.

Run Supervisor

Heartbeat, timeout, cancellation, process isolation, log streaming và resource limit.

Artifact Uploader

Upload report, diff, schema, log và metadata theo content hash.

Credential Provider

Lấy token ngắn hạn cho orchestrator, Git remote và artifact store.

9.4 Wake-up invariant

  • MCP chỉ cung cấp tool cho agent đang chạy.
  • Runner mới là tiến trình luôn sống để nhận task.
  • Assignment phải chứa run_id, attempt, lease_token và deadline.
  • Runner phải ACK trước khi task chuyển ASSIGNED → RUNNING.
  • Mọi result thiếu hoặc sai fencing token đều bị từ chối.

11.2 Constraints quan trọng

  • workspace_registrations unique theo workspace + agent + machine + local repo fingerprint.
  • Mỗi task attempt chỉ có tối đa một active run.
  • Mỗi registration không vượt quá max_concurrency.
  • Artifact content hash là immutable; cùng hash có thể deduplicate storage.
  • Không cho phép cycle trong task DAG và workspace link loại depends_on nếu policy cấm.
  • Result chỉ được nhận khi run state active và lease token hợp lệ.

12. Dependency resolution và scheduling

12.1 Điều kiện task READY

ready(task) =
  all(task_dependencies completed)
  AND all(required artifact selectors resolved)
  AND destination workspace enabled
  AND no policy blocker
  AND attempts < max_attempts

12.2 Chọn registration

eligible(registration, task) =
  registration.status == AVAILABLE
  AND registration.workspace_id == task.workspace_id
  AND registration.capabilities contains task.required_capabilities
  AND registration.active_runs < registration.max_concurrency
  AND registration.last_seen_at within heartbeat threshold
  AND registration satisfies policy / ownership / locality constraints

12.4 Lease protocol

  1. Scheduler transactionally chuyển task READY → ASSIGNED và tạo run.
  2. Lease gồm TTL, heartbeat interval và fencing token tăng đơn điệu.
  3. Runner ACK trong khoảng ngắn; nếu không ACK, lease bị thu hồi.
  4. Heartbeat gia hạn lease; quá hạn chuyển run sang LOST.
  5. Run retry tạo attempt mới và token mới; result cũ không còn quyền cập nhật.

13. Verification và integration

13.1 Verifier checks

Identity

run_id, task_id, attempt và lease token đúng.

Git

Base/head commit tồn tại, remote ref truy cập được, diff nằm trong policy.

Workspace

Không còn uncommitted intended changes và không sửa file bị cấm.

Checks

Test/lint/build bắt buộc pass bằng lệnh trusted hoặc CI.

Artifact

Schema hợp lệ, hash khớp, lineage đầy đủ và không chứa secret.

Contract

OpenAPI/schema parse được, compatibility policy pass và diff được phân loại.

13.2 Integration strategy

Không dùng repo local của nhân sự làm integration authority. Dùng dedicated Integration Runner hoặc CI.

+
Frontend verified refrepo B commit
→

→

13.3 Merge ownership

  • Agent worker chỉ tạo branch/commit cho task của mình.
  • Merge vào protected branch được thực hiện bởi CI, merge bot hoặc integration agent chuyên dụng.
  • Cross-repo feature có thể tạo nhiều PR được liên kết bằng job ID.
  • Completion của job có thể yêu cầu tất cả PR merged hoặc chỉ yêu cầu output verified, tuỳ policy.

14. Security và trust boundary

Orchestrator trust

  • Phát hành short-lived runner token.
  • Không lưu credential Git cá nhân nếu không cần.
  • Authorize theo workspace, registration, role và task.
  • Audit mọi state transition và artifact access.

Runner trust

  • Isolate process theo run.
  • Giới hạn command/tool bằng Wormhole policy.
  • Redact secret khỏi logs và artifact.
  • Không expose inbound port công khai mặc định.

Idempotency rules

  • Mọi write API nhận idempotency_key.
  • complete(run_id) gọi lặp lại với cùng payload phải trả cùng kết quả.
  • Event consumer lưu cursor hoặc event ID đã xử lý.
  • Artifact publish dùng unique constraint theo producer run + logical name + version.

16. Kế hoạch triển khai

Mục tiêu là chứng minh luồng đáng tin cậy trước, sau đó mới tối ưu dynamic scheduling, contract intelligence và nhiều agent vendor.

P0 — Architecture foundation

Deliverables: ADR, domain schema, state machine, API contract, threat model và quyết định deployment topology.

  • Chốt identity của workspace, agent, machine và registration.
  • Chốt Git transport: push branch là mặc định; patch/bundle là fallback.
  • Chốt artifact backend: local filesystem/S3-compatible storage.
  • Chốt runner connection: WebSocket hoặc long-poll.

P1 — Orchestrator core

Deliverables: service skeleton, persistent store, Job/Task APIs, DAG validation và event log.

  • Tạo tables/migrations cho workspace, agent, registration, job, task, run, lease và event.
  • Implement task state machine với transaction boundary rõ ràng.
  • Implement DAG cycle detection và dependency completion logic.
  • Thêm audit correlation: job_id, task_id, run_id, registration_id.

P2 — Resident Agent Runner

Deliverables: runner daemon, registration, heartbeat, assignment stream và generic agent adapter.

  • Runner config local: agent identity, workspace mappings, Wormhole endpoints.
  • Process supervision, log streaming, cancellation và timeout.
  • ACK/heartbeat/complete/fail protocol với fencing token.
  • Single-run concurrency trước; mở rộng multi-run sau.

P3 — Wormhole workspace adapter

Deliverables: preflight, local Git validation, task context bootstrap và post-run inspection.

  • Kiểm tra repo identity, branch, clean state và base commit.
  • Generate agent MCP config trỏ vào fixed local workspace endpoint.
  • Thu changed files, diff summary, test output và commit metadata.
  • Quarantine registration khi workspace state không an toàn.

P4 — Artifact service và verifier

Deliverables: immutable artifact manifest, upload/download, content hash và verification pipeline.

  • Artifact types: commit_ref, patch, report, schema, OpenAPI, logs.
  • Verifier kiểm tra Git remote ref, base/head relation và required checks.
  • Chỉ publish artifact.published sau khi verifier pass.
  • Scoped artifact access cho task consumer.

P5 — Federated same-repo orchestration MVP

Deliverables: hai người, hai local clone, một logical workspace, task dependency và handoff commit.

  • Blob hoàn tất task A và push branch.
  • Task B READY sau khi task A verified.
  • Alice nhận commit/diff artifact, fetch ref và làm tiếp.
  • Chứng minh stale result, runner disconnect và retry an toàn.

P6 — Cross-repo workspace links

Deliverables: WorkspaceLink, Contract Registry, contract artifact và dependency resolver.

  • Backend workspace publish payment-api.
  • Frontend workspace subscribe contract với trigger policy.
  • Task envelope của Alice chứa OpenAPI, API diff, notes và Backend commit.
  • Breaking-change policy tạo approval hoặc migration task.

P7 — Integration runner và quality gates

Deliverables: dedicated CI/integration registration, contract tests, E2E checks và linked PR artifacts.

  • Không merge tại local workspace của nhân sự.
  • Chạy multi-repo E2E với verified refs.
  • Publish final job verdict và release readiness.
  • Tạo conflict/resolution task khi gate fail.

P8 — Production hardening

Deliverables: RBAC, secrets, observability, quotas, HA và operational tooling.

  • Metrics: queue latency, run duration, lease loss, verification failure, artifact size.
  • Tracing xuyên suốt orchestrator → runner → Wormhole.
  • Runner auto-update, version compatibility và drain mode.
  • Backup/restore, event retention và incident runbook.

P9 — Intelligent dependency optimization

Deliverables: usage-aware trigger, semantic artifact summary và scheduler ranking nâng cao.

  • Đọc consumer usage manifest để giảm false trigger.
  • Phân loại API diff: compatible, risky, breaking.
  • Cache artifact theo runner locality.
  • Optional planner agent tạo DAG nhưng phải qua schema validation và limits.

17. Acceptance criteria

MVP same-repo

  • Hai runner trên hai máy đăng ký hai local clone vào cùng logical workspace.
  • Task A hoàn tất và publish remote commit artifact.
  • Task B chỉ READY sau khi commit artifact của A verified.
  • Task B được giao đúng registration còn capacity.
  • Result từ attempt cũ không thể cập nhật task sau retry.
  • Runner mất heartbeat được mark LOST và lease được thu hồi an toàn.

MVP cross-repo

  • Workspace Backend có link provides_api_to Workspace Frontend.
  • Backend publish OpenAPI, API diff, notes và test report có content hash.
  • Frontend task nhận chính xác artifact version đã resolve.
  • Internal Backend refactor không trigger Frontend khi contract không đổi.
  • Breaking API change được phát hiện và áp dụng approval/migration policy.
  • Alice không cần truy cập filesystem local của Blob.
  • Integration runner xác minh hai repository bằng verified refs.

Operational

  • Orchestrator restart không mất job/task/run/lease/artifact state.
  • Mọi transition có audit event với correlation IDs đầy đủ.
  • Artifact download được authorize theo task và hết hạn.
  • Runner có drain, quarantine và manual recovery workflow.
  • Dashboard hiển thị queue, active runs, offline runner và blocked dependencies.
